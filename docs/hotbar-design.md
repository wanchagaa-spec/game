# Hotbar — ช่องถือของ 10 ช่อง

> **สถานะ: ดีไซน์เท่านั้น ยังไม่ได้เขียนโค้ด**
> ช่วงเวลาที่ทำ: **Phase 5.5** (หลัง Phase 4 มีอาวุธแล้ว)
> จดไว้ตอนนี้เพื่อไม่ให้ลืมตอนถึงเวลาทำ · ยังไม่มี schema ยังไม่มี RemoteEvent
> ⚠️ ส่วนขยาย **"หยิบ-วางจริงในโลก 3D"** (ไข่/แม่/ทหาร) เป็น**เฟสแยกทีหลัง** ไม่ได้พ่วงมากับ
> Hotbar พื้นฐานนี้ — ดู [§7](#7-ส่วนขยาย-หยิบ-วางจริงในโลก-3d-เฟสแยก-หลัง-hotbar-พื้นฐานเสร็จ)

## 1. คืออะไร

แถบช่องถือของด้านล่างจอ **10 ช่อง** แบบเดียวกับเกม Roblox แนวขโมยไข่/สะสม
กดเลือกช่องแล้วตัวละคร "ถือ" ของชิ้นนั้น

| | |
|---|---|
| จำนวนช่อง | **10** |
| PC | hotkey `1`–`9` และ `0` (ช่องที่ 10) |
| มือถือ | แสดง **4–5 ช่อง** · แตะเพื่อใช้/ถือ · เลื่อนดูช่องที่เหลือ |
| หน้าตา | **สายรุ้งเน้นขอบช่องที่ถืออยู่** (ตามดีไซน์อ้างอิง) |

## 2. ⚠️ ข้อสำคัญที่สุด: เป็น shortcut ไม่ใช่ inventory ใหม่

**แต่ละช่องคือ "ทางลัดชี้ไปที่ของในกระเป๋าจริง" ไม่ใช่ที่เก็บของอีกที่หนึ่ง**

```
กระเป๋าแม่ (100 ตัว)  ─┐
กระเป๋าไข่ (10,000)   ─┼──► Hotbar 10 ช่อง = ตัวชี้ (pointer) ไปที่ของพวกนี้
คลังลูก (กองละ 500)   ─┤
อาวุธ                 ─┘
```

ถ้าทำเป็น inventory แยกจะเกิดคำถามที่ไม่มีคำตอบดี ๆ ทันที:
ของอยู่ใน hotbar แล้วยังนับในกระเป๋าไหม · ขายแม่ที่อยู่ใน hotbar ได้ไหม ·
เพดานกระเป๋า 100 นับรวม hotbar หรือเปล่า · เซฟสองที่แล้วไม่ตรงกันจะเชื่ออันไหน

**เป็น pointer แล้วคำถามพวกนี้หายไปหมด** — ของมีที่อยู่จริงที่เดียวเสมอ

### แยกจากกระเป๋าเดิมทั้งสองใบ

`Config.Balance.Bag.CAPACITY` (แม่ 100) กับ `Config.Balance.Hatchery.BAG_CAPACITY` (ไข่)
**เป็นคนละเรื่องกับ hotbar** · hotbar ไม่มีเพดานของตัวเอง เพราะไม่ได้เก็บของ

## 3. การสแต็ค — ตามธรรมชาติของของที่ชี้ไป

hotbar **ไม่มีกฎสแต็คของตัวเอง** แสดงตามที่ของจริงเป็นอยู่

| ของ | สแต็คไหม | เพราะ |
|---|---|---|
| **ลูก** | ✅ สแต็ค | เก็บเป็นกองอยู่แล้ว (`stack key` = ตัวละคร + น้ำหนักแม่ + สถานะ) |
| **ไข่** | ✅ สแต็คตาม `eggId` + น้ำหนัก | ไข่น้ำหนักเท่ากันจากด่านเดียวกัน = ของอย่างเดียวกัน |
| **แม่** | ❌ ไม่สแต็ค | แม่เก็บรายตัว มี `uid` ของตัวเอง แต่ละตัวไม่เหมือนกัน |
| **อาวุธ** | ❌ ไม่สแต็ค | มีชิ้นเดียวต่อเลเวล |

⚠️ **ห้ามสร้าง stack key ชุดใหม่ให้ hotbar** ใช้ `Config.makeStackKey()` ของเดิม
(กฎในCLAUDE.md: stack key เป็นโครงหลัก เปลี่ยนแล้วกองลูกของผู้เล่นทุกคนอ่านไม่ออก)

## 4. ⚠️ ปัญหาที่ยังไม่มีคำตอบ — ต้องตัดสินตอนออกแบบจริง

จดไว้ให้ครบตั้งแต่ตอนนี้ เพราะสี่ข้อนี้กระทบโครงสร้าง ไม่ใช่แค่หน้าตา

### 4.1 ของที่ถือในมือแสดงบนตัวละครยังไง

| ของ | ตัวเลือก |
|---|---|
| **อาวุธ** | โมเดลติดมือ (`Tool` หรือ `Motor6D` เข้ากับมือขวา) — ตรงไปตรงมา |
| **แม่ / ลูก / ไข่** | โมเดลลอยข้างตัว? อุ้มไว้หน้าอก? หรือไม่แสดงอะไรเลยนอกจากไฮไลต์ในช่อง? |

⚠️ ถ้าแสดงโมเดลจริงต้องคิดเรื่อง **ผู้เล่น 6 คนถือของพร้อมกัน** = โมเดลเพิ่ม 6 ชิ้นในฉาก
และถ้าถือ "กองลูก 500 ตัว" จะแสดงยังไงให้ไม่กลายเป็น 500 Part
(กฎเดิมของโปรเจกต์: **ลูกไม่แสดงในแมพจนกว่าจะปล่อยออกรบ** — ข้อนี้อาจขัดกัน ต้องตัดสิน)

### 4.2 ของที่ shortcut ชี้ไปหมดแล้วจะทำยังไง

เช่นใส่ไข่ `egg_stage3` น้ำหนัก 500 ไว้ช่อง 3 แล้ววางฟักจนหมด

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **ล้างช่องอัตโนมัติ** | ไม่มีช่องตายค้าง | ผู้เล่นจัดช่องไว้แล้วหาย ต้องจัดใหม่ |
| **ค้างไว้เป็น dim** (เทา กดไม่ได้) | ของมาใหม่แล้วกลับมาใช้ได้ทันที | ถ้าไม่มีวันได้ของนั้นอีก ช่องตายถาวร |

**เอนไปทาง dim** เพราะผู้เล่นจัดช่องตามนิสัยการเล่น ไม่ใช่ตามของที่มีตอนนั้น
แต่ต้องมีวิธีล้างช่องด้วยมือ

### 4.3 ถือแม่/ไข่อยู่ แล้วสั่งงานจากช่องนั้นได้เลยไหม

- ถือไข่ → กดวางลงสวนฟักได้เลย?
- ถือแม่ → กดวางลงคอก / ส่งไปรบได้เลย?

⚠️ **ถ้าส่งแม่ไปรบจากช่องนี้ได้ ต้องผ่านกล่องยืนยันเหมือนเดิม**
และ**เลือกได้เฉพาะแม่ในกระเป๋า** ตามกฎเดิม
(`MOTHERS_SELECTABLE_FROM_PEN = false` ที่ `validate()` ตรึงไว้)
→ แม่ในคอกต้องไม่ขึ้นใน hotbar ตั้งแต่แรก แบบเดียวกับที่ไม่ขึ้นในกระเป๋า

### 4.4 ปุ่มอัปเกรดกับปุ่มร้านค้าอยู่คนละที่

**ปุ่มอัปเกรด damage (72 ขั้น) และอัปเกรดความเร็ว (5 ขั้น) ไม่กินช่อง hotbar**
เป็นปุ่มติดตัวแยกต่างหาก เปิดได้ทุกที่ (กฎเดิม: ไม่ต้องเดินไปร้าน)

hotbar มีไว้สำหรับ **ของที่ถือ** เท่านั้น ไม่ใช่เมนู

## 5. สิ่งที่ต้องเพิ่มตอนทำจริง (ยังไม่ทำ)

- [ ] **schema**: `hotbar` ใน PlayerData — อาเรย์ยาวคงที่ 10 ช่อง ช่องว่างใช้ `false`
      แต่ละช่องเก็บ **ตัวชี้** ไม่ใช่ตัวของ (เช่น `{ kind = "mother", uid = "123-4" }`
      หรือ `{ kind = "child", stackKey = "..." }`) — **ต้องเขียน migration**
- [ ] **RemoteEvent**: ตั้งช่อง · เลือกช่องที่ถือ · ใช้ของในช่อง
      ⚠️ server ตัดสินทุกอย่าง client แค่ส่งว่าอยากทำอะไรกับช่องไหน
- [ ] **validate ฝั่ง server**: ช่องที่ชี้ไปหาของที่ไม่มีแล้ว / ไม่ใช่ของผู้เล่นคนนั้น ต้องปฏิเสธ
- [ ] **UI**: 10 ช่องบน PC · 4–5 ช่องบนมือถือ · ไฮไลต์สายรุ้งช่องที่ถือ
- [ ] **ตัดสิน 4 ข้อใน §4 ก่อนเริ่มเขียน**

## 7. ส่วนขยาย: หยิบ-วางจริงในโลก 3D (เฟสแยก หลัง Hotbar พื้นฐานเสร็จ)

> **สถานะ: แนวคิดเท่านั้น ยังไม่ได้ออกแบบละเอียด ยังไม่ได้เขียนโค้ด**
> ช่วงเวลาที่ทำ: **หลัง Phase 5.5 (Hotbar พื้นฐาน) เสร็จและทดสอบแล้ว** — เป็นเฟสถัดไป
> ไม่ใช่ส่วนหนึ่งของ Phase 5.5 · ยังไม่ได้ตั้งเลขเฟส (รอถึงตอนนั้นค่อยตัดสิน)

### 7.1 ต่างจาก Hotbar พื้นฐาน (§1-6) ยังไง

Hotbar พื้นฐานแค่ "เลือกของที่ถือ" ผ่านเมนู/hotkey — กด `1`-`9`,`0` แล้วของขึ้นในมือ
**แต่ตอนจะใช้ของนั้นจริงยังกดผ่านปุ่ม UI 2D เหมือนเดิมทุกอย่าง** (วางไข่/ย้ายแม่/จัดคิวทหาร)
hotbar พื้นฐานแค่เปลี่ยนว่า **"เลือกอะไร"** ไม่ได้เปลี่ยนว่า **"ใช้ยังไง"**

**ส่วนขยายนี้เปลี่ยน "ใช้ยังไง"** — พอถือของจากช่อง hotbar อยู่ ต้องหยิบ-วางของชิ้นนั้นได้จริง
ในโลก 3D (คล้ายเกมสร้าง/วางของแบบ Roblox ทั่วไป) **แทนที่** ปุ่มเมนู 2D ที่ใช้อยู่ตอนนี้:

| ของ | 2D เดิม (ใช้งานได้ปกติจนกว่าจะถึงเฟสนี้ — ดู §7.4) | 3D ใหม่ (เฟสนี้) |
|---|---|---|
| **ไข่** | ปุ่ม "วางไข่ฟองแรก" ในกริดกระเป๋าไข่ | หยิบไข่จากกระเป๋ามาถือ แล้ววางลงช่องสวนฟักเองในโลก |
| **แม่** | ปุ่ม "ย้ายเข้าคอก/กระเป๋า" ในกริดกระเป๋าแม่ | หยิบจากกระเป๋ามาวางในคอกเอง หรือหยิบจากคอกไปวางในกระเป๋า/พื้นที่ส่งรบ |
| **ทหาร (ลูก/soldiers)** ⚠️ ใหม่ | แผงจัดคิวปล่อยทหาร (`SetReleaseOrderRequest`) — ปุ่มเลื่อนขึ้น/ลงจัดลำดับ `releaseOrder` เปิดเฉพาะตอนเข้าใกล้จุดปล่อย | หยิบทหารจากคลังมาจัดเรียง/วางที่จุดปล่อยเองในโลก 3D |
| **อาวุธ** | (ยังไม่มี UI — Phase 4 ยังไม่เขียน) | ตามแผนเดิม Phase 4-5 |

### 7.2 ทหาร (soldiers) — เรื่องใหม่ที่ยังไม่เคยพูดถึงมาก่อน

แผงจัดคิวปล่อยทหารตอนนี้ (`Main.client.lua` ต่อกับ `Config.RemoteNames.SET_RELEASE_ORDER_REQUEST`)
เป็น **ทางลัดชั่วคราวที่ตกลงกันไว้ตั้งแต่ตอนออกแบบ 3B-1**: เลือกทำ UI 2D (ปุ่มเลื่อนขึ้น/ลง
เรียงลำดับ `releaseOrder`) ก่อน เพราะเร็วกว่าและเสี่ยงน้อยกว่าการทำ interaction 3D ตั้งแต่แรก —
**ไม่ใช่การตัดสินใจถาวร**

เฟสนี้คือจุดที่กลับมาทำเวอร์ชัน 3D จริงตามที่ตั้งใจไว้แต่ต้น: หยิบทหารจากคลังมาจัดเรียง/วางที่
จุดปล่อยเองในโลก แทนปุ่มเลื่อนขึ้น/ลง

⚠️ **ยังไม่ได้ออกแบบรายละเอียด** — ต้องตัดสินอย่างน้อย:
- หยิบ "กองทหาร" (stack) มาวางเป็นยังไง ในเมื่อ 1 กองมีได้ถึง 500 ตัว (ปัญหาเดียวกับ §4.1
  เรื่องแสดงของที่ถือบนตัว — 1 กองไม่ใช่ 1 Part)
- วางแล้วคือ "จัดลำดับ" (`releaseOrder` เดิม) หรือ "สั่งปล่อยจริง" ไปเลย — คนละความหมายกัน
  ต้องเลือกให้ชัดก่อนออกแบบ
- **กฎเดิม "ลูกไม่แสดงในแมพจนกว่าจะปล่อยออกรบ" ต้องยังจริงอยู่** — หยิบทหารจากคลังมาวาง
  "ก่อนปล่อยจริง" ต้องไม่ขัดกับกฎนี้ (อาจต้องมีสถานะ "วางคิวแล้วแต่ยังไม่ปล่อย" ที่ไม่เท่ากับ
  "ปล่อยออกรบแล้ว")
- ผูกกับ `MOTHERS_SELECTABLE_FROM_PEN = false` / แม่ในคอกไม่ขึ้นในกระเป๋าเดิมยังไง ถ้าเฟสนี้
  ไปพร้อมกับ Phase 3C (จัดทีมแม่ไปรบ ยังไม่ทำ) — สองเรื่องอาจเกี่ยวโยงกัน ต้องดูตอนถึงเวลา

### 7.3 ทำไมต้องเป็นเฟสแยก ไม่พ่วงกับ Hotbar พื้นฐาน

**นี่คือการยกระดับจาก UI แบบเมนู (ที่ใช้ตอนนี้ในทุกระบบ) เป็นการโต้ตอบจริงในโลก 3D** —
งานใหญ่กว่า Hotbar ธรรมดามาก (ตำแหน่งวางที่ถูกต้อง/valid ไหม ยืนยันฝั่ง server ตามกฎ
server-authoritative เดิม ผู้เล่น 6 คนหยิบ-วางพร้อมกันในแมพเดียวกันโดยไม่ชนกัน) ควรทำ
**หลัง Hotbar พื้นฐานเสร็จและทดสอบแล้ว** ไม่ใช่พ่วงมาพร้อมกันตั้งแต่แรก

### 7.4 ระบบ 2D เดิมไม่ต้องรื้อตอนนี้

ปุ่มวางไข่ / ย้ายแม่ / แผงจัดคิวปล่อยทหารที่มีอยู่ตอนนี้ **ยังใช้งานได้ตามปกติจนกว่าจะถึงเฟสนี้**
ไม่ต้องแตะ ไม่ต้องรื้อ ไม่ต้องเตรียมอะไรล่วงหน้าตอนนี้เลย
