# แผนจัดหน้าจอใหม่ (UI-1 ถึง UI-5)

> บันทึกการตัดสินใจทั้งหมดของรอบจัด UI ใหม่ ให้รอบ UI-2 ถึง UI-5 อ้างอิงได้โดยไม่ต้องถามซ้ำ
> ต้นแบบ = ภาพ UI จากเกมอื่นที่ผู้ใช้ส่งมา (มือถือแนวนอน 2000 × 921) — **ตำแหน่ง ขนาด สี การจัดวางให้เหมือน**
> แต่ **ไอคอน/รูปทำเองทั้งหมด** (รูปทรงง่าย ๆ · emoji · ViewportFrame จากโมเดลของเราเอง) ห้ามอ้าง asset ของเกมอื่น

## 1. แผน 5 รอบ

| รอบ | งาน | สถานะ |
|---|---|---|
| **UI-1** | จัดหน้าจอ: ช่องถือของ · ปุ่มกระเป๋าด้านบน + กระเป๋า 3 แท็บ · ปุ่มร้านค้า/ดัชนีด้านซ้าย (ยังเปิดแค่หน้า "เร็วๆ นี้") · ปุ่มไข่/ปุ่มเท้าด้านขวา · เลเวลความเร็ว/ดาเมจมุมล่างซ้าย · HUD การรบโชว์เฉพาะตอนเปิดอัญเชิญ · "สวมใส่ที่ดีที่สุด" แบบสลับตัว | ✅ เขียนแล้ว · ทดสอบ Studio บางส่วน → แก้ตำแหน่งรอบ 1 แล้ว (ปุ่มกระเป๋า · HUD การรบ · ยอดเงิน — §3/§4) |
| **UI-2** | ป้ายบนแมพ กด E (`ProximityPrompt`): ป้ายอัปดาเมจอยู่หน้าทางเข้ากำแพง · ป้ายอัปค่าวิ่งอยู่**ซ้าย**ประตูคอก · ป้ายอัปคอกอยู่**ขวา**ประตูคอก · ร้านขายแม่ (ใช้เงินในเกม) ไปอยู่ที่ร้านด้านหลังแมพที่สร้างไว้แล้ว → ลบปุ่มอัปเกรดกับปุ่มขายเดิมออกจากหน้าจอ | ✅ เขียนแล้ว (ยังไม่ทดสอบ Studio) — ตำแหน่งจริง §3 · การตัดสิน §5 |
| **UI-3** | แท่นอัญเชิญ: อยู่หน้าเลนตรงกลาง เอาบล็อกสี่เหลี่ยมเดิมออก ทำเป็นแท่นวงกลมเรืองแสง เดินเข้าใกล้แล้วขึ้นปุ่ม E (⚠️ สร้างด้วย `UiKit.prompt()` → OnePerButton · §5) → หน้าต่าง 2 แท็บ (แม่ / ลูก) ติ๊กได้หลายรายการ **ลำดับการส่ง = ลำดับที่ติ๊ก** · ลูกเก็บเป็น "กอง" ติ๊ก 1 กอง = ส่งทั้งกอง (มาแทนระบบเรียงลำดับปล่อยแบบเดิม) · แม่ติ๊กได้ถึงเพดาน roster แล้วขึ้น**กล่องยืนยันรวมครั้งเดียว**ว่าจะตายถาวร · ปุ่มหยุดอัญเชิญอยู่ในหน้าต่างเดียวกัน → ลบแท็บลูก ปุ่มส่งไปรบ และปุ่มอัญเชิญเดิมทิ้ง | ✅ เขียนแล้ว (ยังไม่ทดสอบ Studio) — ตำแหน่ง §3 · การตัดสิน §6 · เช็คลิสต์ `docs/ui-test-checklist.md` |
| **UI-4** | ดัชนี: 1 ช่อง = 1 ตัวละคร จัดกลุ่มตามคลาส/ความหายาก · ตัวที่ยังไม่เคยได้แสดงเป็นเงาดำ ตัวที่ได้แล้วแสดงรูป · รูปเรนเดอร์จากโมเดลด้วย ViewportFrame · **schema v4** เพิ่มชุด "ตัวที่เคยได้" ผู้เล่นเก่านับจากแม่ที่มีอยู่ตอนนี้ (ตัวที่ขาย/ตายไปแล้วไม่นับ — **ยอมรับแล้ว** เพราะเกมยังไม่เปิดให้เล่น) | ✅ เขียนแล้ว (ยังไม่ทดสอบ Studio) — ตำแหน่ง §3 · การตัดสิน §7 · เช็คลิสต์ `docs/ui-test-checklist.md` §7 |
| **UI-5** | ร้านค้า Robux (ปุ่มซ้าย "🛒 ร้านค้า" เดิม — แทนหน้า "เร็วๆ นี้"): ไข่ตำนาน · ซื้อขั้นดาเมจ/ความเร็ว**ทะลุเพดานแทร็กเงินในเกม** (ตัวเลือก ก — ไม่ใช่ "ยังติดเพดานเหมือนเดิม" ตามที่เคยเขียนไว้ในแถวนี้ ดู §8) · เร่งฟักไข่ทั้งหมด (ปุ่ม "เติบโตทั้งหมด" ในหน้าต่างไข่ — ทำงานจริงแล้ว) · ราคาใส่ 1 Robux ไว้ก่อน · Product ID ใส่ค่าชั่วคราวใน `Config.lua` (ผู้ใช้สร้าง ID จริงบนเว็บ Roblox เอง) · `ProcessReceipt` ให้ของ**ครั้งเดียวต่อใบเสร็จ** | ✅ เขียนแล้ว (ยังไม่ทดสอบ Studio) — การตัดสิน §8 · เช็คลิสต์ `docs/ui-test-checklist.md` §8 |
| **UI-fix รอบ 1** | แก้จากผลทดสอบจริงใน Studio (หลัง UI-1 ถึง UI-4 ผ่านหมดแล้ว): เงินชิดขอบบนสุด · E ค้างที่แท่นอัญเชิญหยุดอัญเชิญได้ทันทีตอนกำลังอัญเชิญอยู่ · ย้ายป้ายดาเมจให้ชัดว่าไม่ใช่โซนคอก · แก้กำแพงปากเลนกระพริบ (z-fighting) + พื้นล้นกำแพง · มาตรฐานสีซื้อ=เขียว/ขาย=แดง · ตกแต่งผิวกำแพงหินขอบแมพ · ขยายแผงไข่/แม่ในคอก | ✅ เขียนแล้ว (ยังไม่ทดสอบ Studio) — การตัดสิน §9 · เช็คลิสต์ `docs/ui-test-checklist.md` §9 |

ของที่**ตัดสินแล้วว่าไม่ทำ**: ปุ่มขวดยา · ปุ่มโหมดช้า · ปุ่มฟันเฟืองในแถบบน

**แผน 5 รอบปิดครบแล้ว (UI-1 → UI-5 เขียนโค้ดเสร็จหมด)** ที่เหลือคือทดสอบรวดเดียวใน Studio ตามลำดับทางเดินจริงในเกม
(`docs/ui-test-checklist.md` §1–8) แล้วค่อย merge — **ห้าม merge จนกว่าผู้ใช้สั่ง**

### ข้อมูลที่ UI-5 ต้องใช้ (ตรวจแล้วว่ามีอยู่ใน Config)
- ตารางคลาสของไข่ตำนาน: `Config.EggCharacterPools.egg_legendary` — B 35% · A 45% · S 18% · **SS 2%** (SS ออกจากไข่นี้เท่านั้น)
- ไข่: `Config.EggTypes.egg_legendary` (`source = "robux"` · `guaranteedTier = 3` · ฟักคงที่ `Balance.Hatchery.LEGENDARY_SECONDS` = 60 วิ)
- Developer Product: `Config.DeveloperProducts.legendary_egg` (`productId = 1000001` placeholder) · `Config.findProductByRobloxId()`
- สินค้า Robux ที่ไม่ใช่ไข่ (ใหม่): `Config.RobuxProducts` — `robux_damage_step` / `robux_speed_step` / `robux_hatch_rush` (`productId = 1000002..1000004` placeholder) · `Config.findRobuxProductByRobloxId()`
- กฎ `ProcessReceipt` (idempotent ด้วย `PurchaseId` · ห้ามคืน `PurchaseGranted` ก่อนเซฟสำเร็จ): `docs/data-schema.md` §8.7

## 2. กติกาช่วงเปลี่ยนผ่าน

ระบบไหนที่ของใหม่จะมาแทนใน**รอบหลัง** → **ห้ามลบในรอบก่อนหน้า** ย้ายไปอยู่ใน**แผง TEMP แผงเดียว**
(ปุ่ม "🛠 TEMP" ด้านซ้ายเหนือปุ่มร้านค้า) ไม่งั้นผู้เล่นใช้ฟีเจอร์นั้นไม่ได้ระหว่างรอบ

✅ **UI-3: ของ TEMP ถูกแทนครบแล้ว — แผง TEMP + ปุ่ม 🛠 ลบทิ้งทั้งหมด** (ไม่มีแผง TEMP เหลือในเกม)

| ของเดิม | อยู่ที่ไหนตอนนี้ (UI-1) | ถูกแทนที่ในรอบ |
|---|---|---|
| ~~ปุ่มอัปดาเมจ / อัปค่าวิ่ง / อัปคอก~~ | **ลบแล้วใน UI-2** → ป้ายบนแมพกด E | ✅ UI-2 |
| ~~ปุ่มขายแม่~~ | **ลบแล้วใน UI-2** → ร้านขายแม่ (แผง 1 หลังแมพ) | ✅ UI-2 |
| ~~ปุ่ม "ขายทั้งหมด (TEMP)"~~ | **ลบแล้วใน UI-1** | — |
| ~~แท็บลูก (กองลูก) / ปุ่มเปิด-ปิดอัญเชิญ~~ | **ลบแล้วใน UI-3** → หน้าต่างแท่นอัญเชิญ (แท็บลูก · ส่งไปรบ / หยุดอัญเชิญ) | ✅ UI-3 |
| ~~แผงเรียงลำดับปล่อย (เปิดใกล้จุดปล่อย)~~ | **ลบแล้วใน UI-3** → ติ๊กเรียงลำดับในแท็บลูก | ✅ UI-3 |
| ~~ปุ่มส่งไปรบ (TEMP) + กล่องยืนยันทีละตัว~~ | **ลบแล้วใน UI-3** → แท็บแม่ + กล่องยืนยันรวมครั้งเดียว | ✅ UI-3 |

## 4. จุดที่ขยับออกจากตัวเลขต้นแบบ (ตัดสินใน UI-1)

- **Hotbar PC 10 ช่อง** ย่อช่องให้อยู่**ระหว่าง**บล็อกเลเวลมุมล่างซ้ายกับที่ว่างขนาดเท่ากันฝั่งขวา (สถิติการรบบน PC อยู่ในที่ว่างนั้น · ความกว้างเดียวกัน) ไม่ใช่แค่ "ไม่ล้นจอ" — ไม่งั้นช่องทับตัวเลขทั้งสองฝั่ง
- **ปุ่มไข่/เท้า** ใช้ `UIAspectRatioConstraint` บังคับจัตุรัส (4.3% × 9.3% เป็นจัตุรัสเฉพาะจอ 2000×921 · จอ 16:9 จะเพี้ยนเป็นสี่เหลี่ยมผืนผ้า)
- **แท็บสัตว์เลี้ยงแสดงแม่ในคอกด้วย** (ป้าย "คอก" สีเขียว เรียงก่อน) — ไม่งั้นล็อกแม่ในคอกไม่ได้ (ถอยหลังจาก Phase 4B)
- **แท็บไข่สแต็คตามชนิด + น้ำหนัก** (ตาม `hotbar-design.md` §3) ไม่ใช่ชนิดอย่างเดียว — ไข่ชนิดเดียวกันน้ำหนักต่างกันเป็นคนละของ วางลงสวนฟักแล้วต้องรู้ว่าวางฟองไหน · เรียงหนักก่อน น้ำหนักเท่ากัน = ด่านสูงก่อน
- ⚠️ **หน่วย GUI บนมือถือเล็กกว่าภาพต้นแบบมาก** (จอ 2000×921 ≈ 844×389 หน่วย) ของเดิมที่เป็น pixel ตายตัวจึงชนกับของใหม่:
  - **ยอดเงิน** (ตัว 52 · กว้าง ~40% ของจอมือถือ) — ขนาดตัวอักษร = min(52, 7.5% ของความสูงจอ) · กว้างได้แค่จากขอบขวาของหลอดเลือด + 12 ถึงขอบจอ (TextScaled + เพดานขนาด) เลขยาวมากย่อลงเองแทนการล้นไปทับหลอด
  - **แผงจัดคิวปล่อย** — ยกขึ้นเหนือแถบ Hotbar (เดิม 100 px จากขอบล่าง ถูก Hotbar ทับบน PC)
- **แก้ตำแหน่งรอบ 1 (ตามผลทดสอบ Studio · client ล้วน ไม่แตะ logic)**:
  - **ปุ่มกระเป๋าแถบบน** เดิมจัดกึ่งกลางแถบ (29/58) แล้วลอยสูงกว่าปุ่มแชท — ปุ่มของ Roblox สูง 44 ห่างขอบบน 12 ในแถบ 58 จุดกึ่งกลางจึงอยู่ที่ **34/58** · ขยายจาก 44/58 เป็น **48/58** · ยังคิดจาก `TopbarInset` ทั้งหมด (เก็บเป็นสัดส่วนของความสูงแถบ ไม่ใช่ pixel)
  - **HUD การรบ** เลิกใช้กล่องมุมขวาบน (+ UIScale) → หลอดเลือดกึ่งกลางบน + สถิติมุมขวาล่าง · ความสูงเป็น pixel แปรตามความสูงจอมีพื้น/เพดาน: ชื่อด่าน 3.2% (12–24) · หลอด 3.6% (14–28) · ช่องว่าง 0.5% (2–6) → มือถือ (389) ทั้งบล็อกสูง 44 · PC 1080 สูง 90
  - **สถิติการรบบนมือถือ** อ่านตำแหน่งปุ่มกระโดดจริงจาก `PlayerGui.TouchGui.TouchControlFrame.JumpButton` (วัดระยะจากขอบล่างจอ ไม่ขึ้นกับว่า TouchGui เว้น inset หรือไม่) · จัดใหม่ทุก sync เพราะปุ่มโผล่/ขยับระหว่างเกมได้ · ไม่มีปุ่ม (PC) = ชิดขอบล่าง 16
  - **ยอดเงินย้ายมุมขวาบน** — ⚠️ ก่อน UI-1 เคยวางมุมขวาบนแล้วชน UI ของ Roblox (ป้ายชื่อผู้เล่น + ยอด Robux) รอบนี้จึงเริ่ม**ใต้** `TopbarInset` · ถ้ายังชนรายชื่อผู้เล่น (PlayerList ที่เปิดด้วย Tab บน PC) ต้องตัดสินใหม่: เลื่อนลง หรือปิด PlayerList
  - ⚠️ **ทับกันที่รู้แล้ว**: มือถือ/แท็บเล็ต เปิดแผงไข่/เท้า (ขวา 41.8–73.3%) พร้อมเปิดอัญเชิญ → แผงทับบรรทัดสถิติการรบบางส่วน (แผงอยู่บน) · มือถือขอบล่างหลอดเลือด (~107) ชิดขอบบนหน้าต่างกระเป๋า (~109) ถ้าแถบบนของ Roblox สูงกว่า 58 จะเกยกัน (หน้าต่างอยู่บน)
- ไอคอนทุกอันเป็น emoji หรือรูปทรงง่าย ๆ · รูปตัวละครในกระเป๋า/แผงเท้า = ViewportFrame จากโมเดลของเราเอง (ตอนนี้มีแค่ลิง) ตัวอื่นเป็นกล่องสีตามคลาส + ตัวอักษรคลาส

## 5. การตัดสินใจใน UI-2 (ป้ายบนแมพ + ร้านขายแม่)

ถามผู้ใช้ก่อนวางเพราะมีหลายตัวเลือก — ได้คำตอบตามที่แนะนำทั้ง 3 ข้อ:

1. **ร้านขายแม่ = แผง 1** (`X −166 · Z −51` ป้ายเดิม "ขายของ · ซื้อไข่") **เปลี่ยนป้ายเป็น "ร้านขายแม่"**
   — ป้ายเดิมมีคำว่า "ซื้อไข่" ซึ่งขัดกฎ (เงินในเกมซื้อไข่ไม่ได้) · แผง 2 "ซื้ออาวุธ" ไม่แตะ (Phase 5)
2. **ซ้าย/ขวาประตู = ยืนบนทางเดินกลางหันหน้าเข้าประตู** — ทุกคนเห็นค่าวิ่งซ้ายมือ อัปคอกขวามือ
   คอกแถวบน/ล่างจึงอยู่คนละฝั่ง X · ป้าย "คอก N" ไม่ย้าย ป้ายฝั่งเดียวกับมันปักถัดออกไป
3. **ป้ายดาเมจ = ปากเลนฝั่งลาน** — เลนใช้ร่วมกันแต่กำแพงกั้นด่านแยกต่อผู้เล่น (client) จุดร่วมจึงต้องอยู่ช่วงที่ทุกคนผ่าน

ตัดสินเองระหว่างทำ (แจ้งในสรุปแล้ว):

- **ข้อความบนป้าย = SurfaceGui ใน PlayerGui** (Adornee = แผ่นป้ายของ server) · **ProximityPrompt สร้างฝั่ง client**
  → ซ่อนจุดกดป้ายคอกคนอื่นได้โดยไม่ต้องให้ server รู้ · ~~ป้ายคอกคนอื่นโชว์ "กดได้ที่คอกของตัวเอง"~~ → ปรับรอบ 1: ไม่แสดงเลย
- **client รู้คอกตัวเองจาก Attribute `PenIndex` บนตัว Player** (`PenService` ตั้งตอนจอง/ล้างตอนคืน) ·
  remote ซื้อ**ไม่ได้อ่านค่านี้** — ไม่ได้เพิ่ม logic ซื้อใหม่ (server ไม่ตรวจระยะ/คอก เหมือนตอนเป็นปุ่มติดตัว)
- **ราคาขายใน sync (`mothersInBag[i].sellPrice`)** — `Config.getMotherSellPrice` คิดที่ server
  (client ไม่มีสถานะของแม่ คิดเองไม่ได้ตรง) ยอดรวมในหน้าต่างขาย = ผลรวมของค่านี้ = เงินที่ได้จริง
- ราคาบนป้ายย่อ (`฿5K`) · **ยอดรวมในร้านขายโชว์เต็มหลัก** (`฿8,250`) ให้เทียบกับเงินที่เพิ่มได้ตรงตัว
- ดาเมจ `damageUpgradeCost = nil` แยกสองกรณี: ยังไม่ถึง 72 ขั้น → "เต็มแล้ว — พังด่านถัดไปเพื่อปลดล็อก" · ครบ 72 → "MAX"
- ร้านขาย: เรียง**ที่ไม่ล็อกก่อน · ราคาถูกก่อน** (ตัวที่มักขายทิ้งอยู่บน) · ปิดหน้าต่าง = ล้างที่ติ๊ก (กันขายตัวที่ลืมว่าติ๊กไว้)
  · sync ใหม่ตัดตัวที่ถูกขาย/ย้าย/ล็อกออกจากที่ติ๊กเอง · "ยกเลิก" ในกล่องยืนยันไม่ส่งอะไร ที่ติ๊กยังอยู่
- **ขายเป็นชุด = `SellMothersBatchRequest(uids)`** (ผู้ใช้อนุมัติ · เพิ่มเติมรอบ 2 ของ UI-2) — ร้านยิงครั้งเดียวต่อชุด
  server ตรวจรูปร่างทั้งชุด (array · string · ≤ ความจุกระเป๋า) → วนแกนขายเดิมทีละตัว ข้ามตัวที่ขายไม่ได้/ซ้ำ →
  sync + ข้อความสรุป**ครั้งเดียว** "ขายแม่ N ตัว ได้ ฿X · ข้าม K ตัว" · `SellMotherRequest` ทีละตัวยังอยู่ (`docs/data-schema.md` §5.5)
- **ProximityPrompt ทุกอัน `Exclusivity = OnePerButton`** (ผู้ใช้สั่ง · เพิ่มเติมรอบ 2) — ป้ายที่อยู่ใกล้กัน
  (ค่าวิ่งคอก 3 `(124.5, 44.2)` กับดาเมจ `(134, 37.5)` ห่าง ~11 studs) ขึ้นเฉพาะอันที่ใกล้สุดต่อปุ่ม
  · **สร้าง prompt ผ่าน `UiKit.prompt()` ที่เดียว** (บังคับค่านี้หลังรับ props) · `tools/check-prompt-exclusivity.py`
  ตรวจว่าไม่มีใครสร้าง prompt เองที่อื่น → **แท่นอัญเชิญ UI-3 ต้องใช้ตัวนี้ด้วย**
  · หมายเหตุ: ค่าตั้งต้นของ Roblox เป็น OnePerButton อยู่แล้ว (รอบก่อนประเมินเกินว่าอาจเห็นปุ่ม E สองอัน) —
  การตั้งตรง ๆ + ตัวตรวจ กันไม่ให้ใครเปลี่ยนเป็น AlwaysShow ทีหลัง

### ปรับตำแหน่งรอบ 1 (ผลทดสอบ Studio)

1. **ร้าน 2 แผงย้ายมาติดกันกลางผนังด้านหลัง** — `Z −51 / +51` → `Z −11 / +11` (X เดิม −166) · ช่องเดินระหว่างแผง

2. **ป้ายค่าวิ่ง/อัปคอกแสดงเฉพาะคอกตัวเอง** — คอกอื่น + คอกที่ไม่มีเจ้าของไม่เห็นป้ายเลย (เดิมโชว์ "กดได้ที่คอกของตัวเอง")
   · เลือกวิธี **server สร้างครบทุกคอกเหมือนเดิม + client ซ่อนในเครื่องตัวเอง** (`LocalTransparencyModifier = 1` ทั้งเสา
   และแผ่น + ปิด SurfaceGui) — ไม่ต้องย้ายการสร้างป้ายไป client และไม่ต้องก๊อปหน้าตาป้ายสองที่

3. **กำแพงข้างเลนที่ปากเลนถอยกลับเสมอกำแพงใส** — ทั้งสองฝั่ง (ข้างคอก 3 และคอก 6 ยื่นเท่ากัน 17.5)
   เริ่ม `X 140` → `X 157.5` (`Config.getLaneWallStartX`) · ต้นเลน/ระยะการรบไม่เปลี่ยน (`docs/map-layout.md` §4)

  เพราะไม่มีสถานะของแม่) → การ์ด "รอผลิต" ที่ยังติ๊กอยู่ตามลำดับ · กองที่หมดและไม่มีแม่ผลิตเติมไม่แสดง หลุดจากลำดับเมื่อส่งชุดใหม่
- **พลังต่อตัว (`power`) คิดที่ server** ใน sync — สูตรเดียวกับที่ปล่อยจริง (รวมสถานะ + `damageLevel`)
- **เหตุผลที่ส่งแม่ไม่ได้ (`sendStageBlockReason`) มาจาก server** — ข้อความเดียวกับที่ server ใช้ปฏิเสธ (แยกเป็น
  `CombatService.getSendStageBlockReason` ใช้ร่วมกับแกนส่งทีละตัว ไม่ได้เขียนกฎใหม่)
- แท็บแม่เรียง **แม่ในสนามบนสุด → แม่ในกระเป๋าคลาสสูง/หนักก่อน** · ติ๊กแม่**ไม่จำ**ข้ามการเปิดหน้าต่าง (ส่งแม่ = ตายถาวร) ·
  ติ๊กลูกกลับมาจาก `releaseOrder` ทุกครั้งที่เปิด · sync ใหม่ตัดติ๊กที่ใช้ไม่ได้แล้วทิ้ง (ส่ง/ขาย/ล็อกทีหลัง · roster เต็มจากที่อื่น)
- เปิดครั้งแรก = แท็บลูก (ใช้บ่อยสุด) · จำแท็บล่าสุดระหว่างเซสชัน
- (ผู้ใช้สั่งเพิ่มหลัง UI-3) **`releaseOrder` ว่าง = ติ๊กทุกกองที่มีของไว้ก่อน** เรียงพลังต่อตัวมาก → น้อย · เอาออกเองได้ ·
  แยก "ไม่เคยติ๊ก" กับ "เคยส่งลำดับว่าง" ไม่ได้โดยไม่แตะ schema → ส่งแม่อย่างเดียวแล้วเปิดใหม่ จะติ๊กทุกกองให้อีกรอบ
- กล่องยืนยันบอกด้วยว่าลูกกี่กองจะถูกปล่อย · ถ้าไม่ได้ติ๊กลูกเลยบอก "ลูกจะไม่ถูกปล่อย"
- ส่งเสร็จ**ไม่ปิดหน้าต่าง** ให้เห็นสถานะเปลี่ยน (🟢 กำลังอัญเชิญ · แม่ในสนาม) · ส่งไม่ได้สักตัวก็ยังตั้งลำดับ + เปิดอัญเชิญตามลำดับยิงที่สั่ง
- ลบปุ่มส่งไปรบ (TEMP) ในหน้ารายละเอียดแม่โดย**ไม่ใส่ปุ่มแทน** · HUD การรบไม่แตะ
- `SendMotherToBattleRequest` (ทีละตัว) · `SetReleaseOrderRequest` · `SetSummonEnabledRequest` ยังอยู่ฝั่ง server ครบ

## 8. การตัดสินใจใน UI-5 (ร้านค้า Robux)

⚠️ **แก้ไขข้อขัดแย้งจากแถวแผนเดิมใน §1**: แถวเดิมเขียนว่าดาเมจ/ความเร็วที่ซื้อด้วย Robux "ยังติดเพดานตามด่านเหมือนเดิม"
แต่โจทย์รอบทำจริง (คุยกันนอกไฟล์นี้) เลือก **ตัวเลือก ก — ทะลุเพดานแทร็กเงินในเกมได้จริง** ยึดตามโจทย์รอบทำจริงเป็นหลัก
(ใหม่กว่า ชัดเจนกว่า) รายละเอียดเต็มอยู่ที่ `docs/data-schema.md` §3.5 + §8.7 นี่คือสรุปการตัดสินใจที่ทำระหว่างเขียนโค้ดจริง:

- **หน้าต่างเป็นก้อนเดียวเลื่อนยาว ไม่ใช่แท็บ** — มีแค่ 4 การ์ดทั้งหมด (ไข่ตำนาน · ทะลุเพดานดาเมจ · ทะลุเพดานความเร็ว ·
  เร่งฟักไข่) หน้าตาต่างกันทุกใบ ไม่ใช่ grid ของสิ่งเดียวกันซ้ำ ๆ แบบดัชนี/กระเป๋า — แท็บจะเกินความจำเป็น
- **ปุ่มซ้าย "🛒 ร้านค้า" เดิมกลายเป็นร้านค้า Robux** ไม่ใช่ปุ่มใหม่แยกต่างหาก — นี่คือปุ่มที่ UI-1 เตรียมไว้เป็น
  placeholder "เร็วๆ นี้" ตั้งแต่ต้นและคอมเมนต์บอกตรง ๆ ว่า "มาในรอบ UI-5" อยู่แล้ว (ร้านซื้ออาวุธเดิมหลังแมพ — Phase 5
  ยังไม่เขียน — เป็นคนละอันไม่เกี่ยวข้องกัน)
- **โบนัสดาเมจ/ความเร็วเก็บเป็น "จำนวนขั้น" แยกฟิลด์ (`robuxDamageBonus`/`robuxSpeedBonus`) ไม่ผสมกับ `damageLevel`/`speedLevel`**
  — สูตรเดิมของแทร็กเงินในเกม (`Config.getArmyDamageMultiplier` / `Config.getWalkSpeed`) **ไม่ถูกแก้เลย** ค่าจริงที่ใช้รบ
  รวมกันตอนคำนวณเท่านั้น (`Config.computeBattlePower(..., robuxDamageSteps)` / `Config.getEffectiveWalkSpeed(...)`)
- **ดาเมจไม่มีเพดาน** เพราะไม่มีค่าคงที่ทางฟิสิกส์ผูกอยู่ (ต่างจากความเร็วที่ผูกกับความหนากำแพง)
- **ความเร็วทะลุเพดานแทร็กปกติ (128) ได้ แต่ clamp ที่ `Config.getRobuxSpeedHardCap()`** ซึ่งคำนวณย้อนกลับจากความหนา
  กำแพงที่สร้างไว้จริง (ไม่ใช่เผื่อความหนาใหม่ให้รับความเร็วที่สูงขึ้น — กันไม่ต้องแตะ `MapDimensions` ที่ล็อกไว้แล้ว)
  รับประกันว่าความเร็วรวมจริงจะไม่มีทางวิ่งทะลุกำแพงที่มีอยู่ ไม่ว่าจะซื้อกี่ขั้นก็ตาม · client ปิดปุ่มซื้อเองตอนถึงเพดาน
  (กันเสีย Robux ฟรี) แต่ server ก็ clamp ผลจริงไว้อยู่ดีไม่ว่า client จะเช็คไหม
- **สินค้า Robux ที่ไม่ใช่ไข่ (ดาเมจ/ความเร็ว/เร่งฟัก) ใช้ Developer Product เดียวซื้อซ้ำได้ต่อชนิด** ไม่ใช่คนละ id ต่อขั้น
  — `ProcessReceipt` ไม่ได้รับพารามิเตอร์ที่ผู้เล่นเลือกไว้ตอนกด (Roblox ไม่ส่งมาให้) จึงให้ `amount` ของสินค้าเองตัดสินว่า
  ซื้อ 1 ครั้งได้เท่าไหร่ ไม่ใช่ตัวธุรกรรม
- **เร่งฟักไข่เลือก "เร่งทั้งหมด" ไม่ใช่ "เร่งฟองที่เลือก"** — เหตุผลเดียวกับข้อบน (ไม่มีทางส่งพารามิเตอร์ "ฟองไหน" ผ่าน

  (เดิมกดไม่ได้ ตอนนี้ทำงานจริง) ปุ่ม ▶ ต่อฟองที่เคยวางแผนไว้ **ถูกถอดออก** (ของซ้ำที่ไม่ได้ implement)
- **idempotency ของ `ProcessReceipt` เก็บที่ `processedPurchaseIds` ใน `PlayerData`** (FIFO 200 รายการ) ไม่เปิด
  DataStore แยกตามที่เคยร่างไว้ (`Config.PurchaseLog` แช่แข็งไว้เผื่ออนาคต) — อะตอมมิกไปกับการเซฟ `PlayerData`
  ก้อนเดียวกันโดยอัตโนมัติ
- **ราคาที่แสดงในหน้าต่างดึงจาก `MarketplaceService:GetProductInfo()` สด ๆ ทุกครั้งที่เปิด** (แคชต่อ productId
  กันยิง network ซ้ำ) — Config ไม่เก็บราคา Robux ตามกฎเดิม (§8.7)
- **placeholder Product ID ทั้ง 4 ตัวรวมอยู่ที่เดียว** (`Config.DeveloperProducts.legendary_egg` + `Config.RobuxProducts`
  ทั้งสามตัว) `validate()` เช็ค unique ข้ามสองตารางเพราะ `ProcessReceipt` รับ `productId` มาเป็นเลขเดียว ไม่บอกว่ามาจาก
  ตารางไหน — ผู้ใช้ต้องสร้าง Developer Product จริง 4 ตัวบนเว็บ Roblox แล้วแทนที่เลขปลอมก่อน publish

  เดียวกับโมเดล mesh ในคอก) ซึ่ง repo นี้ยังไม่มี ส่วน `Material = Rock` ที่ใช้อยู่แล้วให้ลายผิวขรุขระแบบ built-in ของ
  Roblox ฟรีโดยไม่ต้องมี asset — ของที่เพิ่มเข้ามาคือมิติ/สีที่ material เดียวให้ไม่ได้ · ตำแหน่งหย่อมมอสคงที่ (ไม่สุ่ม)
  กันสองผู้เล่นเห็นไม่ตรงกัน (แม้เรื่องนี้ไม่กระทบกติกาเกม) · ไม่แตะขนาด/ตำแหน่ง/`CanCollide` ของกำแพงจริงเลย
