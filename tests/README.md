# tests — ชุดเทสต์ของ Config

## รันยังไง

ต้องมี [luau CLI](https://github.com/luau-lang/luau/releases) (ไฟล์เดียว ไม่ต้องติดตั้งอะไรเพิ่ม)
แล้วรันจาก **รากโปรเจกต์**:

```bash
luau tests/run.luau
```

เท่านี้จบ — ไม่ต้องเปิด Roblox Studio ไม่ต้อง `rojo build` ก่อน ไม่ต้องใช้ Python

ผ่านหมดจะจบด้วย `=== ผ่าน 365 / ตก 0 ===` และ **exit code 0**
มีเทสต์ตกจะพิมพ์รายการที่ตกทั้งหมดแล้ว **exit code 1** (เอาไปต่อ CI ได้ตรง ๆ)

## ทำไมต้องมี

ตัวเลขสมดุลของเกมนี้ผูกกันเป็นลูกโซ่ แก้ตัวเดียวแล้วอีกหลายตัวต้องขยับตาม
และ **ความผิดพลาดแบบนี้มองด้วยตาไม่เห็น** — เคยพลาดมาแล้วหลายรอบ:

| เคยพลาด | ผลที่ตามมา | ตอนนี้จับได้ด้วย |
|---|---|---|
| turret แรงเกิน 17–238 เท่า | ผู้เล่นตีไม่ผ่านเลย | `assertTurretIsSurvivable()` |
| turret อ่อนจนแทบไม่มีผล (0.35%) | ด่านง่ายเกินไปทั้งเกม | เทสต์ TURRET_TOLL |
| ยามผ่านทั้งที่เกมเล่นไม่ไหว | สมมติว่าผู้เล่นมีแม่ที่ต้องฟาร์มหลักแสนชั่วโมง | ยามเวลาฟาร์ม ≤ 5× เวลาตี |
| ราคา upgrade ถูกไป | เงินล้น 299 เท่า ไม่มีอะไรให้ซื้อ | เทสต์ราคากินรายได้ 30–70% |

เทสต์ชุดนี้ไม่ได้เช็คแค่ว่า "ค่าคงที่ตรงตาราง" แต่ **รันพฤติกรรมจริง**:
สุ่มน้ำหนัก 5 ล้านครั้งแล้ววัดการกระจาย · สุ่มตัวละคร 300,000 ครั้งต่อไข่ ·
คำนวณเส้นเวลาครบ 9 ด่าน · และ **ยิงค่าที่ควรพังใส่ยามเพื่อพิสูจน์ว่ายามจับได้จริง**
(ยามที่ไม่เคยถูกทดสอบว่าจับได้ ก็คือยามที่ยังไม่รู้ว่าทำงานหรือเปล่า)

## โครงไฟล์

```
tests/
  run.luau          → ตัวรัน + harness (check / near) + สรุปผล + exit code
  config.spec.luau  → เคสทั้งหมด รับ (t, Config) เข้ามา
```

เพิ่มชุดใหม่: สร้าง `<ชื่อ>.spec.luau` ที่ `return function(t, Config)` แล้วต่อท้ายตาราง `suites` ใน `run.luau`

### ทำไม Config.lua ถึงโหลดนอก Roblox ได้

`Config.lua` ใช้ `Color3` กับ `Vector3` ซึ่งเป็น API ของ Roblox ที่ luau CLI ไม่มี
หัวไฟล์จึงเช็คก่อนแล้ว fallback เป็น table ธรรมดา (บล็อก "ทำให้ไฟล์นี้โหลดได้นอก Roblox")

ใช้วิธีนี้ได้เพราะ **ไม่มีตรรกะไหนในเกมอ่านค่าสีหรือขนาดกลับมาคำนวณ** มีแต่ส่งต่อให้ Roblox วาด

⚠️ ถ้าวันไหนมีคนใส่ API ของ Roblox ตัวใหม่ลง Config ตรง ๆ เทสต์จะพังทันที
**นั่นคือพฤติกรรมที่ต้องการ** — เป็นสัญญาณว่าต้องเพิ่ม fallback ให้ตัวนั้นด้วย ไม่ใช่บั๊กของเทสต์

## ⚠️ สิ่งที่เทสต์ชุดนี้ตรวจไม่ได้ — ต้องเปิด Studio ทดสอบเอง

เทสต์ชุดนี้ตรวจ **`Config.lua` เท่านั้น** ไม่ได้แตะโค้ดใน `src/server` หรือ `src/client` เลย
เพราะโค้ดพวกนั้นเรียก `game:GetService()`, `Instance.new()`, `RemoteEvent`, `Player`
ซึ่ง stub ให้ครบเท่ากับเขียน Roblox ขึ้นมาใหม่ทั้งตัว

รายการที่ยัง**ต้องทดสอบด้วยมือ**ทุกครั้งที่แก้ระบบไข่:

| ต้องทดสอบ | ทำไมอัตโนมัติไม่ได้ |
|---|---|
| **น้ำหนักตอนเป็นไข่ = น้ำหนักแม่ที่ฟักออกมา เป๊ะทุกฟอง** | ต้องมี `Player` จริงกับวงจร `onPlayerAdded` → `grantEgg` → `placeEgg` → `hatch` |
| ย้ายแม่คอก ↔ กระเป๋า และเพดานกระเป๋า 100 ตัว | อยู่ใน `EggService.moveMother` ซึ่งต้องมี state ของผู้เล่นจริง |
| กระเป๋าไข่เต็ม / สวนฟักเต็ม แล้วเพิ่มไม่ได้ | เหมือนกัน |
| ยิง `heldIndex` ผิด ๆ แล้ว server ปฏิเสธโดยไม่ error | ต้องยิงผ่าน RemoteEvent จริง |
| แม่เดินไปมาในคอกจริง ไม่ทะลุรั้ว · ไข่โผล่ในคอก | เป็นการวาดและขยับในโลก 3 มิติ |
| ผู้เล่น 6 คนพร้อมกันในเซิร์ฟเดียว (เต็มพอดีทุกคอก) | ต้องใช้ Studio multi-player test |

**ย้ำ:** ข้อแรกสำคัญที่สุด ถ้าข้อนั้นไม่ผ่าน ที่เหลือไม่ต้องดู

เช็คลิสต์เต็มอยู่ใน [`../docs/map-layout.md`](../docs/map-layout.md) §10 และ [`../docs/phase-1.5-rework.md`](../docs/phase-1.5-rework.md) §8

### แจกไข่มาทดสอบระหว่างที่ยังไม่มีบอส

รันใน **command bar ฝั่ง server** ของ Studio:

```lua
require(game.ServerScriptService.EggService).grantEgg(game.Players.ชื่อผู้เล่น, "egg_stage1")
```

⚠️ เป็นคำสั่งฝั่ง server เท่านั้น ไม่มีปุ่มใน UI — ไข่สร้างจากฝั่ง client ไม่ได้เด็ดขาด
