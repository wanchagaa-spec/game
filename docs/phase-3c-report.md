# Phase 3C — ส่งแม่ไปรบ + ตายถาวร (รายงานสรุป 3C-1 และ 3C-2)

> ✅ **เสร็จทั้งสองส่วนและผ่านการทดสอบใน Studio แล้ว** (ผู้เล่นทดสอบเอง 4 ข้อ ผ่านครบ — ดู §6)
> 3C-1 = ฝั่ง server (ข้อมูล + กติกา + การรบ) · 3C-2 = ฝั่ง client (ปุ่ม + กล่องยืนยัน + HUD)
> เอกสารนี้เก็บไว้เป็นบันทึกว่า "ทำอะไรไป ตัดสินอะไรไว้ และยังขาดอะไร"

---

## 1. ทำไมแยกเป็น 3C-1 กับ 3C-2

โจทย์แรกที่ได้รับคือ **3C-2 (UI ส่งแม่ไปรบ)** แต่ตอนเช็คโค้ดพบว่า**ฝั่ง server ยังไม่มีเลย** —
ไม่มีที่เก็บแม่ที่อยู่ในสนามรบ ไม่มี remote ให้ UI เรียก และไม่มีกติกาการตาย
ทำ UI ก่อนจะต้องเดาสัญญา remote เอง จึงหยุดถามก่อน → ตกลงให้ **ทำ 3C-1 ก่อน แล้วค่อย 3C-2**

## 2. สิ่งที่ตัดสินแล้ว (ตอบ "1" = ตามข้อเสนอทุกข้อ)

| เรื่อง | ตัดสิน |
|---|---|
| แม่ตียังไง | **ตีวินาทีละครั้ง** แรงเท่า `Config.computeBattlePower(weight, charId, statuses, damageLevel)` ของตัวเอง (สูตรเดียวกับลูก → แม่ 1 ตัว = แรงเท่าลูก 10 ตัว) |
| ตีตอนไหน | **เฉพาะตอนเปิดอัญเชิญ** · ปิดอัญเชิญ (รวมตอน auto-pause) = แม่ยืนรอ ไม่ตี ไม่ตาย |
| ค่าเก่า `Inventory.MAX_TEAM_*` | **เก็บไว้ ไม่ลบ** แต่ติดป้ายว่าถูกแทนที่แล้ว (ดีไซน์ "ทีม" ที่ไม่เคยเขียนเป็นโค้ด) |
| ที่อยู่ของแม่ | เพิ่ม **`battleRoster`** เป็นที่อยู่ที่ 3 — แม่ 1 ตัวอยู่ได้ที่เดียว (คอก / กระเป๋า / สนามรบ) |
| ส่งจากไหน | **กระเป๋าเท่านั้น** · ส่งแล้วย้ายออกจากกระเป๋า **ช่องกระเป๋าว่างทันที** |
| เพดาน | **10 ตัว** (`Config.Balance.Combat.MAX_BATTLE_MOTHERS`) |
| ตายเมื่อไหร่ | **ด่านที่กำลังตีพัง = แม่ทั้ง roster ตายพร้อมกัน** · ไม่มีการตายรายตัวระหว่างตี |
| ดึงกลับ | **ไม่ได้** · ไม่มี remote ย้ายออกจาก roster |
| schema | **v1 → v2** มี migration |

## 3. Phase 3C-1 — ฝั่ง server

### 3.1 ข้อมูล (schema v2)
- `PlayerData.battleRoster: { Mother }` — โครงเหมือนแม่ในกระเป๋าทุกฟิลด์
- template ผู้เล่นใหม่ได้ `battleRoster = {}`
- `MIGRATIONS[1]` (v1→v2): ใส่ `battleRoster = {}` ถ้ายังไม่มี · **ไม่แตะฟิลด์อื่น** · เรียกซ้ำได้ (idempotent)
- `buildWorstCase` (วัดขนาดข้อมูลเต็มพิกัด) นับแม่ใน roster 10 ตัวด้วย

### 3.2 Remote ใหม่ `SendMotherToBattleRequest(uid)`
client ส่งแค่ `uid` (string) · ผลกลับทาง `ActionResult` เหมือนปุ่มอื่น · server ตรวจตามลำดับ:

| ลำดับ | เงื่อนไข | ข้อความที่ผู้เล่นเห็น |
|---:|---|---|
| 1 | uid ไม่ใช่ string | ข้อมูลแม่ไม่ถูกต้อง |
| 2 | ไม่อยู่ในกระเป๋าของคนส่ง (แม่ในคอก / แม่คนอื่น / ส่งไปแล้ว) | ส่งไปรบได้เฉพาะแม่ในกระเป๋าของตัวเองเท่านั้น |
| 3 | แม่ถูกล็อก (`locked = true`) | แม่ตัวนี้ถูกล็อกไว้ ส่งไปรบไม่ได้ |
| 4 | roster เต็ม | roster เต็มแล้ว (10/10) |
| 5 | ผ่านครบทุกด่านแล้ว | ผ่านครบทุกด่านแล้ว ไม่มีด่านให้ส่งแม่ไปรบ |
| 6 | ด่านที่กำลังตีมี HP รวม 0 (ด่าน 1) | ด่าน N ไม่มีศัตรูให้ตี — เปิดอัญเชิญให้ผ่านด่านนี้ไปก่อน |
| ✅ | ผ่านทุกข้อ | ส่งแม่ไปรบแล้ว (roster n/10) |

ข้อ 6 กันแม่ตายฟรี: ด่านที่ไม่มีศัตรู "พัง" ทันทีตั้งแต่ตาแรก · `killRoster` กันซ้ำอีกชั้น (ด่าน HP 0 ไม่ฆ่า)

### 3.3 การรบ (`CombatService.tick`)
```
damage ต่อตา = damage ลูกที่ปล่อยจากคิว + (ผลรวม computeBattlePower ของแม่ใน roster × วินาทีที่ผ่าน)
            → ไหลเข้า applyDamageToStage ทางเดียวกัน (ทหารฝ่ายรับก่อน ส่วนเกินไปกำแพง)
ด่านพัง → recomputeWallProgress → killRoster (ล้าง roster ทั้งชุด + stats.mothersLost += จำนวน)
```
- damage ของแม่**ได้เงินจากการฆ่าทหารฝ่ายรับ**ตามสัดส่วน HP เหมือน damage ลูก
- แม่**ไม่นับเป็น "หน่วยที่ปล่อย"** ของ auto-pause (ไม่ได้ผ่านคิวปล่อย)
- uid ของแม่ที่ตาย**ไม่ถูก reuse** (`nextUid` เดินหน้าอย่างเดียวอยู่แล้ว)

### 3.4 ต่อสาย
- `Remotes.lua` สร้าง remote ใหม่ตอนบูต
- `EggService.sendMotherToBattle` เรียก handler → สำเร็จแล้วลองวางแม่ที่ฟักค้าง (ข้อ D) ลงช่องกระเป๋าที่เพิ่งว่าง → sync
- sync ส่ง `battleRoster` (uid · charId · weight · statuses) ให้ client
- `debugResetAll` ล้าง roster ด้วย

## 4. Phase 3C-2 — ฝั่ง client (`Main.client.lua` ไฟล์เดียว)

### 4.1 ปุ่ม "ส่งไปรบ" ในแท็บกระเป๋า
อยู่ในกลุ่มเดียวกับ "ย้ายแม่ที่เลือก → คอก" / "ขายที่เลือก" · สีแดง (สีเสี่ยง แยกจากส้ม TEMP)

| สถานะ | ปุ่มแสดง | กดแล้ว |
|---|---|---|
| ยังไม่เลือกแม่ | เลือกแม่ด้านล่างเพื่อส่งไปรบ (ปิด) | ไม่มีอะไร |
| roster เต็ม | ส่งไปรบไม่ได้ — roster เต็มแล้ว (10/10) (ปิด) | ขึ้นข้อความเดิมในช่องผลลัพธ์ · **ไม่เปิดกล่อง ไม่ยิง remote** |
| ปกติ | ส่งไปรบ (roster n/10) | **เปิดกล่องยืนยันเท่านั้น** |

### 4.2 กล่องยืนยัน
- หัวข้อ **"ส่งแม่ไปรบ?"** · บรรทัด `ชื่อ · คลาส X · น้ำหนัก kg`
- คำเตือนสีแดง **"แม่ตัวนี้จะตายถาวรทันทีที่ด่านที่กำลังตีอยู่พังสำเร็จ ไม่สามารถดึงกลับได้"**
- ปุ่ม **"ยืนยันส่งรบ"** (แดง) · **"ยกเลิก"** (เทา)
- ScreenGui แยก `DisplayOrder` สูงกว่าแผงหลัก + ฉากหลังมืดเต็มจอ กันกดโดนปุ่มข้างหลัง
- จับ uid ไว้**ตอนเปิดกล่อง** (ไม่อ่าน selection ตอนกดยืนยัน — sync ทุก 1 วิอาจล้าง selection ระหว่างนั้น)

**ยืนยัน:** ทั้งไฟล์มี `sendMotherToBattleRequest:FireServer` **จุดเดียว** อยู่ในปุ่ม "ยืนยันส่งรบ"
(เช็ค roster เต็มซ้ำอีกรอบก่อนยิง) · "ยกเลิก" แค่ปิดกล่อง ไม่ส่งอะไรไป server

### 4.3 CombatHud (มุมขวาบน เห็นตลอด)
- บรรทัด **"แม่ในสนามรบ: X/10"** อ่านจาก sync ล้วน ๆ
- รายการย่อ `คลาส น้ำหนัก kg` ของแต่ละตัว ซ่อนตอน roster ว่าง
- กล่อง HUD สูงตามเนื้อหา (`AutomaticSize`) แทนความสูงตายตัว

### 4.4 สิ่งที่ไม่ได้แตะ (ตามโจทย์)
`CombatService` · logic roster · การตายตอนด่านพัง · `TroopRenderer` · `WallRenderer` · `CombatEffects`

## 5. งานเพิ่มหลังทดสอบ — log "คลังลูกเต็ม"

`ProductionService` เดิมพิมพ์ `คลังลูก ... เต็ม (500 ตัว) หยุดผลิตชั่วคราว` **ทุกรอบ settle** ของแม่ทุกตัวที่คลังเต็มค้าง
→ ท่วม console จนอ่าน log อื่นไม่ได้ (เห็นจากภาพทดสอบ)

แก้ให้พิมพ์**เฉพาะรอบที่เพิ่งเต็ม** (ก่อน settle ยังไม่เต็ม · หลัง settle ถึงเพดาน) — `ba01ec1`

⚠️ **ทดสอบใน Studio แล้วยังขึ้นทุก 5 วิ ตอนเปิดอัญเชิญ:** การรบดึงลูกออกจากกองทุกวินาที กองลดลงนิดหน่อย
แล้วแม่เติมกลับถึงเพดานทุกรอบ settle → นับว่า "เพิ่งเต็ม" ใหม่ตลอด (เทสต์รอบแรกไม่ได้จำลองเคสนี้)

**แก้รอบสอง:** แจ้งครั้งแรกที่กองเต็ม แล้วเงียบจนกว่ากองจะลดต่ำกว่า**ครึ่งเพดาน** (250) ค่อยแจ้งใหม่
- จำไว้ในหน่วยความจำเท่านั้น (weak table ผูกกับ `data` ของผู้เล่น — ออกเกมแล้วหายเอง) ไม่แตะข้อมูลที่เซฟ
- ถูกดึงไปรบนิดหน่อยแล้วเติมกลับ → ไม่แจ้งซ้ำ · ถูกดึงจนเหลือต่ำกว่าครึ่งแล้วเต็มใหม่ → แจ้งใหม่ 1 ครั้ง
- สถานะ "แจ้งแล้ว" แยกต่อผู้เล่น · ค่า `hitCap` ที่คืนออกไปความหมายเดิม ไม่กระทบโค้ดอื่น
- ทดลองคืนเงื่อนไขรอบแรก → เทสต์ใหม่ตก (แจ้ง 11 ครั้งแทน 1) ตรงกับอาการที่เห็นใน Studio

## 7. ยังไม่ได้ทำ / ข้อจำกัดที่รู้อยู่

| เรื่อง | สถานะ |
|---|---|
| **แจ้งเตือนตอนแม่ตาย** | `tick` คืน `mothersLost` แล้ว แต่ยังไม่มีใครส่งต่อให้ client · ตอนนี้ผู้เล่นเห็นแค่ HUD กลับเป็น 0/10 |
| **ภาพแม่ในเลนรบ** | แม่ใน roster มองไม่เห็นในสนาม (ไม่ได้แตะ `TroopRenderer` ตามโจทย์) |
| **ปุ่มล็อกแม่** | ฟิลด์ `locked` มีและ server เช็คแล้ว แต่ยังไม่มี UI/remote ให้ผู้เล่นล็อกเอง |
| **HP รายตัว** | ยังเป็นโมเดล HP รวม · แม่ไม่ตายระหว่างตี ตายพร้อมกันตอนด่านพังเท่านั้น (อนาคตดู `docs/combat-hp-vision.md`) |
| **ค่าเก่า `Inventory.MAX_TEAM_*`** | ยังอยู่ใน Config ไม่มีโค้ดใช้ (ตัดสินให้เก็บไว้) |
| **โน้ตเก่าใน `CLAUDE.md`** | ที่บอกว่า "`wallProgress` ยังไม่เชื่อมกับ `stageProgress`" ล้าสมัยแล้ว (มี `recomputeWallProgress` แล้ว) ยังไม่ได้ลบ |
